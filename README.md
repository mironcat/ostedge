# OstEdge

Приложение для выделения контура остракод и измерения их формы.
Это самостоятельная JavaScript-реализация идей Python-пайплайна `run2dmorph`
из AutoMorph, а не обёртка над Python.

Стек: **Electron + Vue 3 + Vite + Element Plus + OpenCV.js (WASM) + SVG.js**.

---

## Что умеет

- Drag & drop изображений (или выбор через диалог).
- Одна раковина на изображение; если объектов несколько — выбирается крупнейший.
- Устойчивый конвейер:
  - grayscale → автоконтраст → размытие;
  - автоопределение полярности (светлый/тёмный объект);
  - порог Оцу или адаптивный порог;
  - морфологическое открытие/закрытие;
  - заполнение дыр, выбор крупнейшего объекта;
  - контур через `findContours` (без хрупкого nearest-neighbor);
  - сглаженный контур для `Rugosity`.
- Измерения: площадь, периметр, большая/малая ось, высота/ширина MBB,
  аспект, эксцентриситет, rugosity, solidity, circularity, эквивалентный диаметр,
  ориентация.
- Визуализация: canvas (изображение + маска) и SVG.js (контур, рамка,
  фиксированные ориентиры, полуточки, центроид).
- Пакетная обработка нескольких изображений.
- Экспорт:
  - **CSV** — таблица измерений (px и выбранные единицы);
  - **TPS** — 2 фиксированных ориентира + N полуточек (по умолчанию 102);
  - **JSON** — полные результаты, параметры и координаты TPS.
- **Калибровка по масштабной линейке**: проведите линию по линейке на
  изображении, введите её известную длину — приложение посчитает единицы на пиксель.
- Отдельный масштаб для каждого изображения; можно применить один масштаб
  ко всем файлам.
- Ручной ввод «единиц на пиксель» и сброс калибровки.

## Требования

- Node.js 20+ (проверено на Node 24).
- Windows / macOS / Linux.
- Для сборки ничего дополнительно не нужно: OpenCV.js копируется из npm-пакета
  автоматически при `npm install`.

## Установка и запуск

Из папки `ostedge`:

```powershell
npm install
npm run dev
```

`npm run dev` поднимает Vite и запускает Electron с горячей перезагрузкой.

Сборка production-версии и запуск:

```powershell
npm run build
npm start
```

> `npm start` загружает `dist/index.html`. Перед ним нужен `npm run build`.

Если файл `public/opencv/opencv.js` отсутствует (например, после чистого клонирования),
выполните:

```powershell
node scripts/copy-opencv.mjs
```

## Как пользоваться

1. Перетащите одно или несколько изображений в окно (или нажмите «Открыть»).
2. Дождитесь окончания обработки — в списке слева появится статус «измерено».
3. Выберите изображение, чтобы увидеть контур и измерения.
4. При необходимости откалибруйте масштаб по масштабной линейке
   (см. раздел «Калибровка по масштабной линейке») или введите единицы
   на пиксель вручную справа.
5. При необходимости поправьте параметры справа — активное изображение
   пересчитывается автоматически через ~350 мс.
6. Для пакетного пересчёта нажмите «Пересчитать все» (или `Ctrl+Enter`).
7. Экспортируйте CSV / TPS / JSON кнопками в шапке.

Горячие клавиши:

- `Ctrl+O` — открыть файлы;
- `Ctrl+Enter` — пересчитать все.

### Визуализация

- **Маска** — голубая заливка найденного объекта.
- **Точки** — полуточки контура (N штук).
- **Рамка** — минимальный описанный прямоугольник и значение аспекта.
- Жёлтые кружки с цифрами — два фиксированных ориентира TPS.
- Белый крестик — центроид.
- Розовая линия — масштабная линейка, по которой выполнена калибровка.

Масштаб изображения меняется ползунком; кнопка «Вписать» возвращает
изображение целиком в окно.

## Калибровка по масштабной линейке

1. Откройте изображение с масштабной линейкой.
2. На панели над изображением нажмите **«Калибровка»**.
3. Кликните начало и конец масштабной линейки. Во время движения мыши
   показывается розовая линия и её длина в пикселях.
4. В открывшемся окне введите **известную длину** линейки (например, 500)
   и выберите единицы (`µm`, `mm`, `nm`).
5. Внизу сразу видно рассчитанное значение, например `0.690000 µm/px`.
6. Нажмите:
   - **«Только этот файл»** — масштаб применяется к активному изображению;
   - **«Ко всем файлам»** — один и тот же масштаб применяется ко всем
     обработанным изображениям (удобно, если у всех снимков одинаковый масштаб).

После применения все длины пересчитываются в выбранные единицы, площадь —
в единицы². Линия калибровки остаётся на изображении (розовая), а текущий
масштаб показывается в панели над изображением.

Масштаб можно также ввести вручную в правой панели или сбросить кнопкой
**«Сбросить масштаб»**. Масштаб хранится отдельно для каждого файла.

## Параметры

| Параметр | Что делает | Как подбирать |
|---|---|---|
| Метод порога | Оцу или адаптивный | Оцу — для равномерного фона; адаптивный — при неравномерном освещении. |
| Полярность | Авто / светлый / тёмный объект | Авто сравнивает среднее по краям и в центре. Если объект тёмный на светлом фоне — «тёмный». |
| Автоконтраст | Растяжение яркости по перцентилям 0.5–99.5 % | Обычно включён. |
| Сдвиг порога | Смещение порога Оцу | `+` — контур худеет, `−` — толстеет. |
| Открытие | Убирает мелкий шум | 3–11 px. Слишком много — теряются детали. |
| Закрытие | Заполняет разрывы | 3–11 px. |
| Размытие | Гауссово размытие | 0–5 px. |
| Сглаживание (rugosity) | Морфологическое открытие для сглаженного контура | 5–15 px; при 1 px Rugosity = 1. |
| Мин. площадь | Отбрасывает слишком мелкие объекты | 10–5000 px. |
| Игнорировать край | Не выбирать объект, касающийся края | Полезно для мусора по краям. |
| Упрощение контура | `approxPolyDP` для отображения | 0–0.5 %. На измерения не влияет. |
| Точек контура (TPS) | N полуточек | В TPS будет N + 2 ориентира. |
| Створка | LV / RV / без ориентации | Меняет направление обхода и стартовую точку TPS. |
| Единиц на пиксель | Масштаб активного изображения | Введите вручную (например, 0.69 µm/px) или откалибруйте по масштабной линейке. Если не задан — всё в пикселях. |

## Измерения

| Показатель | Формула / смысл |
|---|---|
| `Area` | Количество пикселей объекта (заполненная маска). |
| `Perimeter` | Длина контура (`cv.arcLength`). |
| `MajorAxisLength` / `MinorAxisLength` | Оси эллипса из центральных моментов: `4·√λ`. |
| `Eccentricity` | `√(1 − λ₂/λ₁)`; 0 — круг. |
| `Height` / `Width` | Длинная/короткая сторона минимального описанного прямоугольника. |
| `AspectRatio` | `Height / Width`. |
| `Rugosity` | `Perimeter / Perimeter(сглаженного контура)`. |
| `Solidity` | `Area / Area(выпуклой оболочки)`. |
| `Circularity` | `4πA / P²`. |
| `EquivalentDiameter` | `2·√(A/π)`. |
| `Orientation` | Угол большой оси к горизонтали. |

Если задан `unitsPerPixel`, длины умножаются на него, а площадь — на его квадрат.
Единицы отображаются в интерфейсе и пишутся в CSV.

## TPS

Каждый блок TPS содержит:

```
LM=102
<x1> <y1>
...
<x102> <y102>
ID=<имя файла>
SCALE=1
```

- Первые два ориентира — левая и правая крайние точки (для LV) или
  правая и левая (для RV).
- Остальные N — равномерно пересэмплированные по длине дуги полуточки.
- Координаты центрированы по центроиду и перевёрнуты по Y (как в Python-версии).
- Если масштаб задан, координаты сразу в выбранных единицах, поэтому `SCALE=1`.

## Тесты

Проверка ядра на реальных изображениях и сравнение с Python:

```powershell
npm run test:core
```

Скрипт обрабатывает `ostracods_edges2.png` и 6 кропов из `demo/input_montage`,
сравнивает площадь/оси/аспект с Python CSV и проверяет экспорт CSV/TPS/JSON.

Electron smoke-тест (скрытое окно, проверка OpenCV, обработки и калибровки):

```powershell
npm run build
npx electron scripts/smoke-test.cjs
```

Ожидаемый результат: `status: "done"`, `tpsCount: 102`,
`unitBefore: "px"`, `unitAfter: "µm"`.

> Встроенный отладочный хук `window.__ostedge` доступен в renderer для
> smoke-теста и ручной проверки из DevTools.

## Ограничения и планы

- Пока поддерживаются PNG, JPG, WebP, BMP, GIF. **TIFF не поддерживается**
  браузерным canvas — конвертируйте в PNG.
- Одна раковина на изображение. Для монтажей используйте `split_objects.py`
  из Python-части проекта или подавайте уже вырезанные файлы.
- Масштаб хранится отдельно для каждого изображения. Если у всех снимков
  одинаковый масштаб, при калибровке выберите «Ко всем файлам».
- `rembg`/AI-удаление фона не переносилось: приложение рассчитано на уже
  вырезанные изображения с тёмным или светлым однородным фоном.
- Упаковка в `.exe` уже настроена — см. раздел ниже.

## Сборка для Windows

`electron-builder` уже добавлен в `devDependencies` и настроен в поле `build`
файла `package.json`. Все команды выполняются из папки `ostedge`.

### 1. Распакованное приложение (быстрая проверка)

```powershell
npm run pack
```

Результат: `release\win-unpacked\OstEdge.exe`.
Можно запускать сразу, без установки.

### 2. NSIS-установщик

```powershell
npm run dist:win
```

Результат: `release\OstEdge-0.1.0-x64.exe`.
Обычный установщик: выбор папки установки, ярлыки на рабочем столе и в меню «Пуск».

### 3. Portable EXE

```powershell
npm run dist:win:portable
```

Результат: `release\OstEdge-0.1.0-portable.exe`.
Один файл, установка не требуется.

### 4. Сборка одной командой

```powershell
npm run package:win
```

Скрипт `scripts\build-windows.ps1` проверит зависимости и соберёт установщик.
Варианты:

```powershell
npm run package:win:portable
npm run package:win:unpacked
```

Можно вызвать и напрямую:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1 -Portable
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1 -Unpacked
```

### Иконка

Иконка приложения уже лежит в `build\icon.png` и подключена через
`build.win.icon`. Перерисовать её можно так:

```powershell
node scripts/make-icon.mjs
npm run dist:win
```

### Подпись кода (Windows)

Без сертификата сборка работает, но Windows SmartScreen предупреждает
при запуске. Если у вас есть сертификат `.pfx`:

```powershell
$env:CSC_LINK = "C:\certs\ostedge.pfx"
$env:CSC_KEY_PASSWORD = "пароль"
npm run dist:win
```

Для сертификата из хранилища Windows задайте в `package.json` → `build.win`:

```json
"certificateSubjectName": "CN=Your Company"
```

и запустите сборку. Переменные `CSC_LINK` / `CSC_KEY_PASSWORD`
(или `WIN_CSC_LINK` / `WIN_CSC_KEY_PASSWORD`) также можно задавать в CI.
